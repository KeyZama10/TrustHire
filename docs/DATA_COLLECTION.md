# Custom interview test set — recording protocol & labelling kit

Public deepfake datasets are not interview-shaped. This kit produces **30–50 simulated interviews** with
time-stamped ground truth, which the harness turns into the ablation, per-attack, calibration and fairness
results. Everything here is tooling: **no numbers exist until you record the sessions.**

## 0. Ethics and consent (do this first)

* Every person whose face or voice is recorded **or synthesised** signs the consent form below. Face-swap and
  voice-clone targets must be consenting participants of the study (never public figures, never non-participants).
* Store raw data only under `~/.trusthire/data/custom` (outside the repo/OneDrive); never commit recordings.
* Delete synthetic media after the study. Report only aggregate results.

> **Consent template.** "I agree to be recorded on video and audio in simulated job interviews for the
> TrustHire research project at <institution>. I agree that my face and voice may be used, with my knowledge,
> to create synthetic (face-swapped / voice-cloned) versions for detector evaluation only. Recordings and any
> synthetic media will be stored securely, not published, and deleted by <date>. I may withdraw at any time."
> Name / signature / date.

## 1. Session design

Aim for ≥ 10 participants; each records 3–5 short sessions (4–6 min). Target mix (≈ 40 sessions):

| Attack (`attack`) | Sessions | How to produce it |
|---|---|---|
| `genuine` | 12 | Candidate answers naturally. |
| `face_swap` | 6 | Real-time face swap with **DeepFaceLive** (DFM model of a *consenting* participant) routed as a virtual camera (OBS Virtual Camera). |
| `voice_clone` | 6 | Voice conversion with **RVC** (real-time) or TTS of another *consenting* participant (e.g. XTTS-v2 / OpenVoice), played into a virtual microphone (VB-Audio Cable). |
| `face_and_voice` | 3 | Both of the above. |
| `proxy` | 5 | Participant A enrolls (ID photo + voice sample), participant B takes the interview (switch mid-session for half of them). |
| `scripted_reading` | 6 | Candidate reads answers generated by an LLM from a second screen / notes. |
| `second_person` / `phone_use` | 2 | A helper whispers or the candidate checks a phone. |

Mid-session switches (genuine → attack) are valuable: they test the *timeline*, not just session labels.

## 2. Recording protocol

1. Start a TrustHire session in the dashboard (Live interview) **or** record with OBS (1280×720, 25–30 fps,
   AAC 48 kHz) and upload later. Record what the interviewer would receive (i.e. after the virtual cam/mic).
2. Enrollment: ID photo (phone photo of an ID card or a passport-style picture) + 10 s voice sample reading
   the sentence shown in the dashboard. For proxy sessions enroll person A.
3. Ask 6 questions from the bank below; press **Mark question asked** (or `Q`) when each question ends, so
   response latency can be measured.
4. Write down the wall-clock of every attack start/stop (or speak a code word) for labelling.
5. Vary conditions across sessions and log them in the manifest: lighting (`bright`/`normal`/`dim`/`backlit`),
   webcam (`720p-laptop`, `1080p-usb`, `phone`), network bitrate (throttle with `clumsy`/browser devtools to
   300/800/1500 kbps), accent (self-described), glasses (yes/no), skin tone (Fitzpatrick I–VI, self-reported, optional).

**Question bank:** introduce yourself · describe a project you are proud of · a technical concept from your
resume in depth · a conflict in a team and how you handled it · why this role · a question that requires
thinking (e.g. estimate the number of …).

## 3. Files and labelling schema

```
~/.trusthire/data/custom/
  manifest.csv
  recordings/<session_id>.mp4
  enroll/<participant>_id.jpg   enroll/<participant>_voice.wav
  resumes/<participant>.pdf
  labels/<session_id>.json
```

`manifest.csv` columns: `session_id, participant_id, recording, attack, id_photo, voice_sample, resume,
lighting, accent, webcam, bitrate_kbps, gender, skin_tone, glasses, notes` (`attack` = the main attack of the
session; allowed values in `trusthire.evaluation.dataset.Attack`).

`labels/<session_id>.json` — non-overlapping segments covering the recording:

```json
{"session_id": "s007", "segments": [
  {"start": 0.0,   "end": 92.5,  "label": "genuine"},
  {"start": 92.5,  "end": 241.0, "label": "face_swap", "tool": "DeepFaceLive 1.x", "notes": "model of p03"}
]}
```

A window counts as fraudulent if ≥ 50 % of it lies inside a non-genuine segment.

## 4. Commands

```bash
python -m trusthire.evaluation.harness template   # creates the folder skeleton + example row
python -m trusthire.evaluation.harness validate   # checks files, labels, overlaps
make eval-custom                                   # extract -> ablations -> report
python -m trusthire.transcript.train               # learn the scripted-answer detector
python -m trusthire.evaluation.harness train-final # ship calibrated fusion models to the live system
```

Results land in `results/custom/` (`ablation.md/.tex`, `per_attack.md`, `fairness.md`, `roc_ablation.png`,
`reliability.png`, `results.json`) and are pulled into `docs/report/paper.md`.
